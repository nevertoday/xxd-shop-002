### まず名前を覚えて、食べたくなって、注文する

<a href="README.md">简体中文</a> · <a href="README.en.md">English</a> · <strong>日本語</strong> · <a href="README.ko.md">한국어</a> · <a href="README.ar.md">العربية</a>

**看板料理ごとに、名前を覚えてもらい、食べたくさせ、注文につなげるメイン画像を。**
料理名は看板クラスの見出し、料理が画面の中心、少しのおすすめスタンプが注文の決め手を後押しします。

| ひと目で分かる | |
|---|---|
| **渡すもの** | 料理名（必須）と写真（推奨）。価格、量など載せたい情報 |
| **受け取るもの** | デリバリーアプリのメイン画像、メニュー画像、看板ライトボックス、ポスター |
| **スタイルの特徴** | 看板サイズの料理名 · 近くておいしそうな料理 · 湯気とつや · 控えめなスタンプ · にぎやか、または爽やかな背景 |
| **向いている用途** | デリバリーアプリ、注文ミニアプリ、店頭ライトボックスの看板メニュー |

> **インストールしたら、こう言うだけ：**
>
> /xxd-shop-002 うちの青山椒よだれ鶏の冷やし麺です。デリバリーアプリのメイン画像を作って

## 解決すること

デリバリーアプリやメニューでは、何十枚もの料理写真が1画面にひしめき、お客さんは一瞬しか見ません。おいしい料理が負ける理由は3つ。名前が小さすぎる、料理が食欲をそそらない、ステッカーを重ねすぎて安売り感が出る。

**Shop 002** は、お客さんが決める順に画面を並べます。**料理名**は看板クラスの見出し、**料理**が絶対的な中心、**おすすめスタンプ**が判断を助け、小さな文字は補足だけ。大きな文字で惹きつけ、スタンプで判断させ、小さな文字で注文へ。

## スタンプの出どころ

| スタンプ | 誰が決めるか |
|---|---|
| 看板、必食、店主のおすすめ、手作り、味のタグ | 料理に合わせて生成 |
| 新作、限定、本日のおすすめ | あなたが言ったときだけ |
| 売れ筋、人気、販売数、受賞 | 本当の情報を提供したときだけ |

だから画像はそのままプラットフォームに載せられます。根拠のない「販売数 No.1」で通報される心配はありません。

## 用意するもの

- **料理名**（必須）：省略せずに。「冷やし麺」より「青山椒よだれ鶏の冷やし麺」。
- **写真**（推奨）：盛り付け、器、具材の割合はそのまま残します。なければ名前・地方の味・主な具材から組み立てます。
- **お店の個性**（任意）：にぎやかな地元の店か、洗練された新しい店か。文字と背景がこれで決まります。
- **価格・量・創業年・ランキング**（任意）：伝えたときだけ載せます。

## 使い方

### ステップ 1：インストール（1回だけ）

```bash
git clone https://github.com/nevertoday/xxd-shop-002.git
mkdir -p ~/.claude/skills
ln -s "$(pwd)/xxd-shop-002" ~/.claude/skills/xxd-shop-002
```

Codex を使う場合は、同じフォルダを `~/.codex/skills/xxd-shop-002` にリンクしてください。インストール後は AI アシスタントのセッションを再起動します。

### ステップ 2：やりたいことを普通の言葉で言う

```text
/xxd-shop-002 うちの青山椒よだれ鶏の冷やし麺です。デリバリーアプリのメイン画像を作って
/xxd-shop-002 写真なし：潮汕牛肉団子ビーフン、手打ちの牛肉団子。1:1 と 3:4 を1枚ずつ
/xxd-shop-002 店頭ライトボックス用の看板焼き魚：2〜3人前 ¥98、2012年創業
```

覚えるフラグはありません。サイズや枚数など決めていないことは一度にまとめて質問され、次回は前回の設定を再利用できます。

### ステップ 3：そのあと何をするか

1. 商品画像と説明を読み、まだ決まっていないことだけを質問します。サイズは用途から、ピクセル数付きで提案します。
2. サイズごとに構図を新しく作り、別の画像から切り抜くことはありません。
3. 納品前に1枚ずつ確認します。商品は変わっていないか、文字のつづりは正しいか、渡していない数字はないか。通らないものは報告して作り直します。
4. PNG を `~/Desktop/xxd/xxd-shop-002/` の下の新しいタスクフォルダに保存し、パスを伝えます。

## よくある質問

**セットメニューも作れますか？**

1枚で主役にするのは看板料理1品です。それが目を引く理由です。セットなら1品ずつ1枚にしてください。

**どのサイズを使えばいいですか？**

デリバリーアプリは 1:1、ライトボックスやポスターは 3:4 か 2:3。

**何が必要ですか？**

3つです。① Claude Code や Codex など、Skills に対応した AI アシスタント。② 画像を生成できるモデル。アシスタント内蔵の画像生成、または Codex に設定したモデルプロバイダーで Responses API 経由で画像を生成するもの（既定は GPT Image 2）。③ Pillow 入りの Python 3.11 以上（`pip install pillow`）。

**お金はかかりますか？商用利用できますか？**

Skill は無料でダウンロードできます。画像生成の費用はあなた自身のモデルアカウントに請求されます。自分の商品・ショップ・ブランド（従業員として勤務先のものも含む）の画像づくりは、申請なしで商用利用できます。Skill の転売、有料サービス化、他人のための有償の画像制作には、事前に作者の書面による許可が必要です。末尾の「ライセンス」を参照してください。

**画像の大きさは？**

比率か正確なピクセル数を指定できます。実際のサイズはモデルが返したとおりで、こっそり拡大することはなく、ファイル名に本当のピクセル数が書かれます。

**画像内の文字に誤字は出ますか？**

AI の画像では、ときどき文字を間違えたり、ブランド名の横に ® のような小さな記号を足したりします。納品前に1枚ずつ拡大して確認し、通らないものは作り直します。このページの作例はすべてその確認を通っています。

**価格や販売数をでっち上げませんか？**

しません。価格、仕様、産地、販売数、受賞、認証など事実に見えるものは、あなたが提供したものか、商品にはっきり読める文字からだけ取ります。それ以外は載せず、「¥XX」の仮置きもしません。

**たくさんの商品を一度に処理できますか？**

できます。商品画像のフォルダを渡してください。1枚の画像に商品1つ、サイズと文字は一度だけ質問され、ある商品の事実やコピーが別の商品に混ざることはありません。

## 原則

- **スタイルは忠実に：** この Skill の背後には成熟した商業デザインのプロンプトがあります（[原文プロンプト](references/original-prompt/zh-CN.md) · [英語の参考訳](references/original-prompt/en.md)）。Skill はそれを書き換えたり、独自の色やアートディレクションを足したりせず、あなたの商品、サイズ、文字、事実をモデルに渡すだけです。
- **商品をデザインし直さない：** 商品画像があれば、形、色、パッケージの文字、ロゴは写真どおりです。
- **あなたの事実だけ、** そして商品はそれぞれ独立。ほかの商品、以前の結果、作例から何も借りません。
- **本物の PNG ビットマップ。** SVG やコードで描いた絵を画像として出すことはなく、実行のたびに新しいタスクフォルダを作ります。
- 料理ごとに別タスクで生成し、他の料理の名前・スタンプ・コピーを借りることはありません。
